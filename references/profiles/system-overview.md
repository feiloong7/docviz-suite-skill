# 系统介绍 / 架构文档 Profile

## 识别信号

文档重点描述系统定位、用户/消费者、模块、组件、技术架构、数据流、接口、外部依赖、部署、调用链、状态、可靠性或安全边界。典型词：系统、架构、模块、服务、接口、数据流、部署、依赖、调用、组件、拓扑。

## 理解重点

1. **系统上下文**：系统目标、边界、用户、上游/下游和外部参与者。
2. **模块与职责**：逻辑分层、模块职责、所有权和相互关系。
3. **数据与调用**：数据来源/去向、读写方向、协议、同步/异步、关键请求链。
4. **状态与生命周期**：核心实体或任务的状态、迁移、重试和终态。
5. **部署与边界**：环境、节点、网络、安全边界、存储和第三方服务。
6. **非功能要求**：性能、容量、可用性、安全、审计、监控、容灾和兼容性。
7. **未知项**：文档没有说明的协议、组件或部署细节必须保持未知。

## 计划摘要模板

- 系统定位与一句话工作方式。
- 系统边界及外部参与者。
- 核心模块和职责。
- 一条关键数据流或调用链。
- 部署/安全边界与外部依赖。
- 状态、异常、非功能约束。
- 文档缺口与需架构师确认项。

## 图形选择

- 理解页：系统上下文、输入/处理/输出、核心模块、关键链路、边界与风险。
- 总览：模块职责和关系，不等同于部署拓扑。
- Archify：组件关系用 architecture；数据处理用 dataflow；请求链用 sequence；状态用 lifecycle。
- Flowchart：系统内部控制流程、批处理、异常和重试；不要用流程图冒充架构图。
- 思维导图：完整模块、接口、部署和非功能要求基线。
- Graphify：组件—接口—数据—依赖—部署节点关系，用于路径查询和影响面分析。

## 质量门槛

- 明确区分逻辑架构、物理部署和运行时调用，不在一张图中混淆层次。
- 箭头方向必须有语义：调用方向、数据方向或控制方向只选一种并配图例。
- 外部系统与内部组件视觉区分；安全/网络边界只按文档绘制。
- 保留真实产品名、协议、端口、环境和接口名；文档未写时不猜。
- 对自动从代码补充的结构单独标注证据来源，不与文档陈述混为一谈。
